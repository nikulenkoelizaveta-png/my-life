# My Life: как устроена система

Этот файл описывает планер целиком, чтобы его можно было менять в новом разговоре без истории старого.

## Коротко

My Life — личный планер для телефона и компьютера. Это одна веб-страница. Код лежит на GitHub, а записи хранятся в базе Supabase. Посмотреть записи можно только после входа по почте и паролю.

| Что | Где |
|---|---|
| Адрес планера | https://nikulenkoelizaveta-png.github.io/my-life |
| Код | GitHub, репозиторий `nikulenkoelizaveta-png/my-life` (открытый) |
| Сайт | GitHub Pages: ветка `main`, папка `/` (root) |
| Записи | Supabase, проект **My Life** (id `oyvxcdoguysvzzyyrugp`, регион eu-west-1, бесплатный тариф) |
| Вход | Supabase Auth: почта и пароль, пользователь один (владелица), регистрация новых пользователей выключена |
| Защита от паузы базы | GitHub Actions, `.github/workflows/keepalive.yml`, раз в день |

В том же аккаунте Supabase есть второй проект, **planerv**. Это отдельный рабочий продукт, к планеру он отношения не имеет, менять его нельзя. Репозиторий `kabinet` на GitHub тоже не относится к планеру.

## Файлы в репозитории

```
index.html                       весь планер: разметка, стили и код в одном файле
docs/SYSTEM.md                   этот файл

README.md                        краткое описание
.github/workflows/keepalive.yml  ежедневный запрос к базе, чтобы бесплатный Supabase не засыпал
```

Сборки нет. Что лежит в `index.html` на ветке `main`, то и показывается на сайте. После каждого изменения GitHub Pages обновляет сайт примерно за 1–2 минуты.

## Как устроен index.html

Файл идёт сверху вниз в таком порядке:

1. **`<head>`**: подключение библиотеки `@supabase/supabase-js@2.45.4` с cdn.jsdelivr.net и иконка.
2. **`<style>`**: внешний вид. В начале блок `:root` с цветами и шрифтами (это токены), затем тёмная тема: блоки `@media (prefers-color-scheme: dark)` и `:root[data-theme="dark"]`. Все цвета берутся из токенов. Шрифт Geologica из Google Fonts.
3. **Разметка**: заголовок «My Life», выпадающее меню разделов (`.menu`), область `#view`, куда рисуется текущий раздел, и панель `#tools` с кнопками «Скачать копию», «Загрузить копию» и «Выйти».
4. **`<script>`**: весь код. Основные части:
   - `TABS` — список разделов в меню. Порядок в массиве совпадает с порядком в меню.
   - `KEYS` и `DEF` — какие наборы данных есть и как выглядит каждый, пока он пустой.
   - `CALT` — пункты выпадающего списка «Тип календаря».
   - Работа с базой: `sb` (клиент Supabase), `loadAll`, `persist`, `commit`, `showLogin`, `start`, `backup`, `init`.
   - Разделы: каждый рисует своя функция `vИмя()`, которая возвращает HTML-строку.
   - `render()` перерисовывает меню и текущий раздел. Таблица соответствия разделов и функций находится внутри `render`.
   - Графики: `chart()` рисует линии, `bars()` — столбцы, `ring()` — кольцо процента. Всё на SVG, без библиотек.
   - События: в самом конце, через делегирование. Клики идут через атрибут `data-act`, формы через `data-form` в обработчике `submit`, галочки и списки через `change`.

### Разделы, которые сейчас в меню

| Раздел (`TABS`) | Функция | Данные (`KEYS`) | Что внутри |
|---|---|---|---|

| Самочувствие (`mood`) | `vMood` | `mood` | ежедневно три ползунка от 0 до 10: тревожность, усталость, довольство жизнью; средние за 7 дней и график за 30 дней |

| Цикл (`cycle`) | `vCycle` | `cycle` | отметки месячных, симптомы, пометки, прогноз по среднему |
| Финансы (`money`) | `vMoney` → `vSave` / `vCredit` / `vPlan` | `wallet`, `plan` | три подраздела (переключатель вверху, состояние `ftab`): «Накопление» — 4 валюты и цель по накоплениям (`goalPanel`); «Кредит» — остаток, история и график; «Финансовый план» — поступления по месяцам и траты, расписанные под каждое поступление |

### Скрытые части

Эти разделы убраны из меню, но код и данные остались:

- `goals` (функция `vGoals`): цели с задачами. Владелица собиралась переделать цели по-новому. В Supabase цели не переносились, старый вариант остался только в прежней версии планера на Claude.
- `sleep` (`vSleep`): сон.
- `english` (`vEng`): английский и домашние задания.

Чтобы вернуть раздел, добавьте его обратно в `TABS`. Если раздел больше не нужен совсем, удалите функцию и ключ, но сначала проверьте, что ключ не используется в других местах (например, `english` и `goals` упоминаются в `monthGrid` и `vCal`).

## Как хранятся данные

### Таблица в Supabase

```sql
public.docs (
  user_id    uuid  -- владелец записи, по умолчанию auth.uid()
  key        text  -- имя набора данных: 'tasks', 'wallet', 'health' и т.д.
  data       jsonb -- весь набор целиком, одним JSON
  updated_at timestamptz,
  primary key (user_id, key)
)
```

- **Одна строка на каждый ключ из `KEYS`.** Любое изменение перезаписывает строку этого ключа целиком (upsert).
- **Политики RLS:** пользователь читает и меняет только строки, где `user_id = auth.uid()`. Анонимный доступ к таблице закрыт.
- **Функция `public.ping()`** возвращает текущее время и доступна анонимно. Её вызывает `keepalive.yml`.
- **Ключ в коде публичный, это нормально.** В `index.html` и `keepalive.yml` лежит publishable-ключ (`sb_publishable_...`). Без входа он даёт доступ только к `ping`. Ключ `service_role` и пароли в код класть нельзя никогда.

### Формат данных по ключам

Даты везде записываются строкой `ГГГГ-ММ-ДД`. Поле `p:'m'` означает, что известен только месяц, а `p:'y'` — что известен только год.

```js
tasks:    { items: [{ id, date, title, time, cat: 'work'|'life', done }] }
dates:    { items: [{ id, date, title, yearly }] }
payments: { items: [{ id, title, amount, kind: 'monthly'|'once', day | date, paid: { 'ГГГГ-ММ' | 'once': true } }] }
inbox:    { items: [{ id, text, kind: 'task'|'idea', created }] }
mood:     { days: { 'ГГГГ-ММ-ДД': { a, f, s, note? } } }   // a тревожность, f усталость, s довольство, 0–10
cycle:    { days: { 'ГГГГ-ММ-ДД': { flow: 0–3, sym: [..], note } } }
wallet:   { rub, usd, eur, cny,                       // накопления
            gRub, gUsd, gEur, gCny,                   // цель в рублях по каждой валюте
            rUsd, rEur, rCny,                         // курс к рублю, вводится вручную
            debt, debtPay, debtDay, debtPaid: { 'ГГГГ-ММ': true },
            debtLog: [{ id, date, p?, amount, note }] }
health:   { height, measures: [{ id, date, p?, weight, waist, hips, chest }],
            labs: [{ id, date, p?, name, value, unit, ref }] }
home:     { notes, meters: [{ id, date, name, value }] }
plan:     { items: [{ id, date, amount, title, out: [{ id, amount, title }] }] }   // поступление и траты, на которые оно распределено
goals:    { items: [{ id, title, hz: 'year'|'5y'|'other', due, why, done, steps: [{ id, title, due, done }] }] }  // скрыто
sleep:    { nights: { 'ГГГГ-ММ-ДД': { bed, wake, wakes, feel? } } }                                              // скрыто
english:  { days: { date: 'yes'|'no' }, hw: [{ id, title, due, done }] }                                         // скрыто
```

При загрузке каждый набор накладывается на свой пустой вариант из `DEF` (функция `merge`). Поэтому новое поле можно спокойно добавить в `DEF`: у старых записей оно появится само.

## Как вносить изменения

### Добавить раздел

1. Добавьте ключ данных в `KEYS` и его пустой вариант в `DEF`.
2. Напишите функцию `vНазвание()`, которая возвращает HTML. Используйте готовые классы: `.panel`, `.stats` и `.stat`, `.list`, `.tbl`, `.btn`, `.btn.primary`, `.f` для полей, `box()`/`chart()`/`bars()` для графиков.
3. Добавьте пункт в `TABS`, а функцию впишите в таблицу соответствия внутри `render()`.
4. Формы: `<form data-form="имя">`, обработка в `submit`. Внутри поменяйте `S[ключ]` и вызовите `commit('ключ')`: это сохранит набор и перерисует экран.
5. Удаление: кнопка `del('ключ_из_LISTS', id)`. Для списков заведите запись в объекте `LISTS`. Удаление подтверждается вторым нажатием («Точно удалить?»).

### Чего не делать

- **Не переименовывайте ключи** в `KEYS`. Иначе старые записи перестанут подхватываться, потому что они лежат в базе под старым именем.
- **Не меняйте формат существующих полей** без переноса данных.
- **Не трогайте проект planerv** в Supabase и репозиторий kabinet.
- **Не выключайте `keepalive.yml`**, иначе база уснёт после недели без запросов.

### Проверить перед выкладкой

- Страница открывается без ошибок в консоли.
- На ширине телефона (около 390px) нет горизонтальной прокрутки. Планером пользуются в основном с телефона.
- Работают светлая и тёмная тема.

## Резервные копии

- **Скачать копию:** кнопка внизу планера сохраняет файл `my-life-копия-ДАТА.json` со всеми наборами `{ app: 'my-life', version: 1, saved, data: { ключ: ... } }`.
- **Загрузить копию:** восстанавливает все наборы из такого файла и перед этим просит подтверждение.
- **Из Supabase напрямую:** Table Editor → таблица `docs`.

## Если что-то сломалось

- **Планер пишет, что записи не загрузились.** Проверьте, не на паузе ли проект My Life в Supabase. Если на паузе, нажмите Restore project. Затем откройте вкладку Actions в репозитории и проверьте, что `Keep database awake` выполняется без ошибок.
- **Забыт пароль.** Supabase → Authentication → Users → у пользователя «Send password recovery» или задать новый пароль.
- **Сайт не обновился после изменений.** Откройте Settings → Pages: источник должен быть `main` / `(root)`. Посмотрите статус сборки во вкладке Actions.
